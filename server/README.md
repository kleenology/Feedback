# خادم رموز التحقق

يرسل رمز الدخول عبر **مزوّد رسائل سعودي** — فيظهر اسم المرسل «كلينولوجي» بدل رقم غريب — ويصكّ للعميل رمز دخول لفايربيس. لا يحتاج ترقية مشروع فايربيس إلى Blaze.

```
التطبيق ──POST /api/otp/send──►  الخادم ──► مزوّد الرسائل ──► جوال العميل
التطبيق ──POST /api/otp/verify─►  الخادم ──► رمز دخول مخصّص ──► فايربيس
```

## ليش خادم أصلاً؟

مفتاح المزوّد والرمز نفسه **ما ينفع يكونان داخل الصفحة** — أي أحد يفتح «مصدر الصفحة» ويقرأهما، فيرسل رسائل على حسابك أو يدخل بأي رقم. التحقق لازم يصير في مكان لا يراه العميل.

## ١) مزوّد الرسائل

سجّل في **مسجات** أو **تقنيات** أو **يونيفونك**، واطلب اعتماد **اسم المرسل** — يحتاج السجل التجاري وياخذ أياماً (هيئة الاتصالات تعتمده، مو المزوّد).

> تقدر تشغّل كل شي قبل الاعتماد بمزوّد `mock`: يطبع الرمز في سجل الخادم بدل ما يرسله.

## ٢) حساب خدمة فايربيس

**⚙️ Project settings ← Service accounts ← Generate new private key** — ينزّل ملف JSON، منه ثلاث قيم.

## ٣) النشر على Vercel

اربط المستودع، واضبط **Root Directory = `server`**، ثم المتغيرات:

| المتغيّر | القيمة |
|---|---|
| `OTP_SECRET` | أي نص طويل عشوائي — يُجزّأ به الرمز |
| `SMS_PROVIDER` | `msegat` أو `taqnyat` أو `unifonic` أو `mock` |
| `SMS_SENDER` | اسم المرسل المعتمد |
| `SMS_KEY` | مفتاح المزوّد |
| `SMS_USER` | اسم المستخدم (مسجات فقط) |
| `FB_PROJECT_ID` | `kleenology-d23a3` |
| `FB_CLIENT_EMAIL` | من ملف حساب الخدمة |
| `FB_PRIVATE_KEY` | من الملف — الصقه كما هو بأسطره |
| `ALLOWED_ORIGINS` | `https://kleenology.github.io` |
| `OTP_DAILY_CAP` | سقف الرسائل اليومي (افتراضي 300) |

## ٤) وصل التطبيق بالخادم

في `app/index.html` غيّر:

```js
var OTP_API='https://<مشروعك>.vercel.app';
```

فاضي = يرجع لرموز فايربيس (وتحتاج Blaze). فيه قيمة = يستخدم خادمك.

## الحدود المدمجة

| الحدّ | القيمة | ليش |
|---|---|---|
| مهلة بين رسالتين | ٦٠ ثانية | يمنع استنزاف الرصيد برقم واحد |
| رسائل الرقم في الساعة | ٥ | نفس السبب |
| سقف يومي عام | `OTP_DAILY_CAP` | يحدّ الفاتورة مهما صار |
| صلاحية الرمز | ٥ دقائق | |
| محاولات الرمز | ٥ ثم يُلغى | يمنع تجربة الأرقام واحداً واحداً |

الرمز يُخزَّن **مجزّأً** (HMAC-SHA256 بسرّ الخادم) لا صريحاً، ويُحذف بمجرد استخدامه. وفشل الإرسال يحذفه فوراً حتى لا يبقى رمز صالح ما وصل أحداً.

## الاختبار

```bash
cd server && node test/run.js
```

١٣ فحصاً بلا شبكة ولا فايربيس: الحدود، انتهاء الصلاحية، المحاولات، رمز رقم آخر، الأصول المسموحة.

## نقطة تحتاج تأكيدك

شكل طلب كل مزوّد في `api/_lib/sms.js` مكتوب من توثيقهم المنشور، لكن **راجعه مرة واحدة** عند الربط — بعضهم يغيّر المسارات. التغيير في دالة واحدة، وبقية النظام لا يتأثر.
