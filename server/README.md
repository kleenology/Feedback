# خادم رموز التحقق

يرسل رمز الدخول عبر **مزوّد رسائل سعودي** — فيظهر اسم المرسل «كلينولوجي» بدل رقم غريب — ويصكّ للعميل رمز دخول لفايربيس. لا يحتاج ترقية مشروع فايربيس إلى Blaze.

```
التطبيق ──POST /api/otp/send──►  الخادم ──► مزوّد الرسائل ──► جوال العميل
التطبيق ──POST /api/otp/verify─►  الخادم ──► رمز دخول مخصّص ──► فايربيس
```

## ليش خادم أصلاً؟

مفتاح المزوّد والرمز نفسه **ما ينفع يكونان داخل الصفحة** — أي أحد يفتح «مصدر الصفحة» ويقرأهما، فيرسل رسائل على حسابك أو يدخل بأي رقم. التحقق لازم يصير في مكان لا يراه العميل.

## ١) مزوّد الرسائل

سجّل في **مسجات** أو **تقنيات** أو **يونيفونك**، واطلب اعتماد **اسم المرسل** — يحتاج السجل التجاري وياخذ أياماً (هيئة الاتصالات تعتمده، مو المزوّد).

> تقدر تشغّل كل شي قبل الاعتماد بمزوّد `mock`: يطبع الرمز في سجل الخادم بدل ما يرسله.

## ٢) حساب خدمة فايربيس

**⚙️ Project settings ← Service accounts ← Generate new private key** — ينزّل ملف JSON، منه ثلاث قيم.

## ٣) النشر على Vercel

اربط المستودع، واضبط **Root Directory = `server`**، ثم المتغيرات:

| المتغيّر | القيمة |
|---|---|
| `OTP_SECRET` | أي نص طويل عشوائي — يُجزّأ به الرمز |
| `SMS_PROVIDER` | `msegat` أو `taqnyat` أو `unifonic` أو `mock` |
| `SMS_SENDER` | اسم المرسل المعتمد |
| `SMS_KEY` | مفتاح المزوّد |
| `SMS_USER` | اسم المستخدم (مسجات فقط) |
| `FB_PROJECT_ID` | `kleenology-d23a3` |
| `FB_CLIENT_EMAIL` | من ملف حساب الخدمة |
| `FB_PRIVATE_KEY` | من الملف — الصقه كما هو بأسطره |
| `ALLOWED_ORIGINS` | `https://kleenology.github.io` |
| `OTP_DAILY_CAP` | سقف الرسائل اليومي (افتراضي 300) |
| `OTP_TEST_NUMBERS` | أرقام تجريبية `رقم:رمز` بفواصل — مثال: `0500000001:123456` |

## الأرقام التجريبية — تحتاجها مرّتين

رقم في `OTP_TEST_NUMBERS` **ما تُرسَل له رسالة** ورمزه ثابت، لكن الحدود تنطبق عليه كغيره.

**لك:** تختبر الرحلة كاملة بلا تكلفة وبلا انتظار اعتماد اسم المرسل.

**لمراجع آبل:** حطّه في **App Review Information ← Sign-in required** مع الرمز. بدونه المراجع يقف على شاشة الدخول ويرفض التطبيق — ما عنده رقم سعودي يستقبل عليه.

> رمز الرقم التجريبي **ما يفتح أي رقم آخر**، ولا يقبل الرقم التجريبي رمزاً غيره. الاثنان مُختبَران.

## أسرع طريق لدخول شغّال اليوم

تقدر تشغّل الدخول **قبل** ما يُعتمد اسم المرسل:

1. انشر الخادم بـ`SMS_PROVIDER=mock`
2. حط رقمك في `OTP_TEST_NUMBERS`
3. اضبط `OTP_API` في التطبيق

الآن تدخل برقمك ورمزك الثابت، وكل شي بعد الدخول حقيقي: الطلبات في Firestore، ولوحة الإدارة تستقبل. لما يُعتمد اسم المرسل، غيّر `SMS_PROVIDER` و`SMS_KEY` و`SMS_SENDER` — ولا شي غيرها.

## واتساب أولاً، وSMS احتياطي

الخادم يقدر يرسل الرمز على **واتساب** ويرجع لـ**SMS** تلقائياً. التحكم بمتغير واحد:

| `OTP_CHANNELS` | السلوك |
|---|---|
| `sms` (الافتراضي) | رسالة نصية فقط — نفس السلوك القديم |
| `whatsapp,sms` | واتساب أولاً، ولو رفضت Meta الإرسال فوراً ← SMS |

**ليش فيه زر «أرسله برسالة نصية» في التطبيق؟** Meta ترد بنجاح حتى لو رقم العميل ما عليه واتساب، والفشل يوصل بعدين. فالتطبيق يكتب «أرسلنا الرمز على واتساب»، وبعد ٢٠ ثانية يظهر زر يطلب الرمز بـSMS (`via:'sms'`) — مهلته ٢٠ ثانية بدل الدقيقة، والسقف بالساعة واليومي يبقى كما هو.

### إعداد واتساب (WhatsApp Cloud API من Meta)

1. **Meta Business** موثّق ← **WhatsApp Manager** ← أضف رقماً (يُفضّل رقم مخصص للرموز).
2. أنشئ قالباً فئته **Authentication** باسم `kleenology_otp` ولغة **Arabic**، مع زر **Copy code**. Meta تكتب نص القالب بنفسها لهذي الفئة.
3. أنشئ **System User** دائم وأعطه صلاحية الرقم، وولّد له **Access token** دائم.
4. المتغيرات:

| المتغيّر | القيمة |
|---|---|
| `OTP_CHANNELS` | `whatsapp,sms` |
| `WA_PROVIDER` | `meta` (أو `mock` للتجربة: يطبع الرمز في السجل) |
| `WA_PHONE_ID` | **Phone number ID** من WhatsApp Manager — مو رقم الجوال نفسه |
| `WA_TOKEN` | الـ Access token الدائم |
| `WA_TEMPLATE` | اسم القالب (افتراضي `kleenology_otp`) |
| `WA_LANG` | لغة القالب (افتراضي `ar`) |
| `WA_API_VERSION` | اختياري (افتراضي `v21.0`) |

> متغيرات SMS (`SMS_PROVIDER` وغيرها) تبقى لازمة — هي الاحتياط.

## ٤) وصل التطبيق بالخادم

في `app/index.html` غيّر:

```js
var OTP_API='https://<مشروعك>.vercel.app';
```

فاضي = يرجع لرموز فايربيس (وتحتاج Blaze). فيه قيمة = يستخدم خادمك.

## الحدود المدمجة

| الحدّ | القيمة | ليش |
|---|---|---|
| مهلة بين رسالتين | ٦٠ ثانية | يمنع استنزاف الرصيد برقم واحد |
| رسائل الرقم في الساعة | ٥ | نفس السبب |
| سقف يومي عام | `OTP_DAILY_CAP` | يحدّ الفاتورة مهما صار |
| صلاحية الرمز | ٥ دقائق | |
| محاولات الرمز | ٥ ثم يُلغى | يمنع تجربة الأرقام واحداً واحداً |

الرمز يُخزَّن **مجزّأً** (HMAC-SHA256 بسرّ الخادم) لا صريحاً، ويُحذف بمجرد استخدامه. وفشل الإرسال يحذفه فوراً حتى لا يبقى رمز صالح ما وصل أحداً.

## الاختبار

```bash
cd server && node test/run.js
```

٢٧ فحصاً بلا شبكة ولا فايربيس: الحدود، انتهاء الصلاحية، المحاولات، رمز رقم آخر، الأصول المسموحة، وواتساب مع الرجوع لـSMS وشكل طلب Meta.

## نقطة تحتاج تأكيدك

شكل طلب كل مزوّد في `api/_lib/sms.js` مكتوب من توثيقهم المنشور، لكن **راجعه مرة واحدة** عند الربط — بعضهم يغيّر المسارات. التغيير في دالة واحدة، وبقية النظام لا يتأثر.
